# 《智趣 AI 闯关学习小程序》用户系统扩展 · 需求分析文档

> 本文档是在核心 MVP（输入 → AI 出题 → 答题 → 复盘报告 → 分享海报）已完成的基础上，追加「用户系统及用户相关功能」的**需求分析**。
> 本文档只描述“做什么 / 做到什么程度”，**不含技术方案设计**（数据库表、接口协议、鉴权实现等留待方案设计阶段）。
> 关联文档：`需求分析文档.md`（总需求）、`《智趣 AI 闯关学习小程序》方案设计文档.md`（核心 MVP 方案）、`prototypes/`（UI 原型 v1.2）。

## 1. 背景与目标

### 1.1 背景

当前项目已跑通核心学习闭环，但用户体系仍是“临时占位”状态：

- 登录页（原型 S1）仅为占位：点击“微信一键登录”只弹提示，实际走“先逛逛”直接进首页。
- 个人资料、经验值（XP）、最近闯关记录**全部存在小程序本地存储**里，换设备即丢失、无法跨端、无法服务端统计。

因此需要补齐一套**真正的用户系统**，把“身份 + 资产（XP）+ 学习记录”从“端上本地”升级为“服务端账户”。

### 1.2 目标

1. 用户可通过微信登录，获得稳定的服务端账户身份。
2. 用户的个人资料（昵称、头像）由服务端管理并可展示、可编辑。
3. 用户的经验值（XP）由服务端权威累计，不再依赖端上本地存储。
4. 用户的闯关历史（最近闯关 / 历史记录 / 基础统计）落到服务端，可跨端查看。
5. 全程**不破坏**现有匿名体验：未登录（“先逛逛”）仍可正常闯关，数据回退到本地。

### 1.3 已确认的关键前提（人工确认结论）

| 项 | 结论 |
| --- | --- |
| 功能范围 | 微信登录 + 账号体系 + Token 鉴权、服务端个人资料 + XP、服务端闯关历史 |
| 登录方式 | 开发模式登录：真实登录架构（`wx.login → code → 后端签发 Token`），是否调用微信 `code2session` 由配置开关控制；缺少 AppSecret 时走 dev 兜底登录，将来填入凭证即切真实 |
| 数据持久化 | MySQL |
| UI 范围 | 只做原型已覆盖的界面：登录页（S1）、“我的”页、首页“最近闯关”；**不新增无原型的页面** |

### 1.4 本次明确不做（超出范围，后续版本再议）

以下需求文档中的 P1/P2 能力**不在本次范围**：

1. 错题本（收集答错题目、回看讲解）。
2. 艾宾浩斯遗忘曲线复习提醒 / “旧识重温”宝藏关卡。
3. 学习分析看板（知识点掌握树、图表统计等新页面）。
4. 社交对战 PK、排行榜、VIP 付费等。

## 2. 需求批次与优先级总览

按“地基优先、可独立交付、逐批递进”的原则拆分为 4 个批次。每个批次都能独立联调、独立验收；后一批次依赖前一批次。

| 批次 | 优先级 | 主题 | 一句话目标 | 依赖 |
| --- | --- | --- | --- | --- |
| 批次一 | **P0（地基）** | 用户登录与鉴权 | 用户能微信登录并获得服务端身份，请求可携带登录态；匿名仍可用 | 无 |
| 批次二 | **P0** | 用户信息获取与展示 | 登录后能获取并展示个人资料，支持编辑昵称/头像 | 批次一 |
| 批次三 | **P1** | 闯关记录落库与 XP 同步 | 通关后把本局记录写入服务端并权威累加 XP | 批次一 |
| 批次四 | **P1** | 闯关历史与统计展示 | 首页“最近闯关”与“我的”统计改为读取服务端数据 | 批次三 |

> 建议交付顺序：批次一 → 批次二 → 批次三 → 批次四。批次三/四是“写入”与“读取”的一对，可连续开发。

## 3. 批次一（P0· 地基）：用户登录与鉴权

### 3.1 需求描述

打通“微信登录 → 服务端识别身份 → 后续请求带登录态”的完整链路，并保留匿名可用。

### 3.2 功能点

1. **微信一键登录**：登录页（原型 S1）点击“微信一键登录”，走 `wx.login` 拿到临时凭证 `code`，提交后端换取用户身份并签发登录态（Token）。
2. **登录双模式（配置开关）**：
   - 真实模式：后端用 AppID + AppSecret 调用微信换取用户唯一标识。
   - 开发兜底模式：未配置 AppSecret 时，后端用一个稳定的开发用标识建立/复用同一个开发账户，保证本地可跑通全链路。
3. **登录态携带与校验**：登录成功后，客户端持有 Token 并在后续需要身份的请求中自动携带；后端校验通过才返回受保护数据。
4. **登录态失效处理**：Token 失效 / 缺失时，受保护接口返回统一的“未登录/登录过期”信号，客户端据此清除本地 Token 并引导重新登录。
5. **匿名兼容**：保留“暂不登录，先逛逛”入口，未登录用户仍可完整闯关；此时用户相关数据回退到端上本地（现状行为）。

### 3.3 涉及界面（仅原型已有）

- 登录页（S1）：把占位登录改为真实登录行为；“先逛逛”保持匿名。

### 3.4 验收标准

- [ ] 点击“微信一键登录”后，能成功获得登录态并进入首页。
- [ ] 开发兜底模式下（无 AppSecret）：本地能登录成功，且多次登录复用同一个开发账户。
- [ ] 真实模式下（填入 AppID/AppSecret）：能正确换取微信身份并登录，无需改动业务代码。
- [ ] 携带有效登录态可访问受保护数据；无/失效登录态时返回明确的“未登录/过期”信号。
- [ ] 未登录用户点击“先逛逛”仍可正常完成一局闯关（不被登录拦截）。

## 4. 批次二（P0）：用户信息获取与展示

### 4.1 需求描述

登录后，用户的个人资料由服务端提供并在“我的”页展示，支持基本编辑。

### 4.2 功能点

1. **获取个人资料**：登录后可从服务端获取当前用户资料（昵称、头像等基础信息）。
2. **资料展示**：“我的”页在登录态下展示服务端返回的昵称、头像与 XP（视觉沿用原型，不新增元素）。
3. **资料编辑**：支持修改昵称、头像（微信头像/昵称获取用当前官方推荐方式）。
4. **登录态区分展示**：
   - 已登录：展示真实资料。
   - 未登录：展示登录入口/引导（视觉保持原型风格，不新增布局），点击可进入登录页。

### 4.3 涉及界面（仅原型已有）

- “我的”页：数据源在登录态下切换为服务端；匿名态显示登录引导。
- 登录页（S1）：作为资料编辑所需授权/登录的入口复用。

### 4.4 验收标准

- [ ] 登录后进入“我的”，展示的昵称、头像、XP 来自服务端。
- [ ] 修改昵称/头像后，服务端保存成功并在页面即时生效。
- [ ] 未登录进入“我的”，展示登录引导且不报错；点击可进入登录。
- [ ] “我的”页整体视觉与原型 v1.2 一致，未新增原型外的元素。

---

## 5. 批次三（P1）：闯关记录落库与 XP 同步

### 5.1 需求描述

把“通关后产生的一局学习记录 + 经验值奖励”从端上本地升级为服务端权威存储。

### 5.2 功能点

1. **通关记录写入**：一局闯关结束（生成复盘报告后），登录用户把本局结果（主题/题数/答对数/正确率/用时/本局 XP/星级等）写入服务端。
2. **XP 服务端权威累计**：本局 XP 由服务端累加进用户总 XP，作为唯一权威口径（避免端上被篡改）。
3. **匿名回退**：未登录用户维持现有本地记录与本地 XP 逻辑，不写服务端。
4. **数据一致性**：同一局不重复写入（避免报告页反复进入导致重复计分）。

### 5.3 涉及界面（仅原型已有）

- 答题页 / 报告页：在通关结算时机触发记录写入（无新增 UI，仅数据链路变化）。

### 5.4 验收标准

- [ ] 登录用户通关后，服务端新增一条对应的闯关记录。
- [ ] 登录用户通关后，服务端总 XP 按本局奖励正确增加。
- [ ] 未登录用户通关后，仍走本地记录与本地 XP（服务端无写入）。
- [ ] 同一局结算不产生重复记录 / 重复加 XP。

### 5.5 待确认项

- [ ] `todo 确认`：一局的 XP 计算口径以谁为准（沿用现有“每答对 +10 XP”前端口径，还是由服务端按答对数重算）。倾向服务端按答对数重算以保证权威。

## 6. 批次四（P1）：闯关历史与统计展示

### 6.1 需求描述

首页“最近闯关”和“我的”统计从本地存储改为读取服务端历史数据。

### 6.2 功能点

1. **最近闯关列表（首页）**：登录用户首页“最近闯关”展示服务端历史（标题、题数、时间、星级、正确率），支持“再战”。
2. **历史记录列表（我的）**：登录用户“我的”页展示历史闯关列表。
3. **基础统计**：“我的”页统计项（闯关次数、平均正确率、累计经验）改为基于服务端数据计算。
4. **匿名回退**：未登录用户维持读取本地记录（现状）。
5. **空态**：无历史记录时展示与原型一致的空态文案。

### 6.3 涉及界面（仅原型已有）

- 首页（S2）“最近闯关”区块。
- “我的”页历史列表与统计区块。

### 6.4 验收标准

- [ ] 登录用户首页“最近闯关”展示服务端历史，字段与原型一致。
- [ ] 登录用户“我的”历史列表与统计（次数/平均正确率/累计 XP）来自服务端且数值正确。
- [ ] “再战”能基于历史主题重新发起一局。
- [ ] 未登录时读取本地历史，行为与现状一致。
- [ ] 有/无记录两种状态展示均与原型 v1.2 一致。

## 7. 通用需求与约束（贯穿所有批次）

1. **匿名可用**：任何批次都不得让“先逛逛”匿名用户无法完成核心闯关闭环。
2. **UI 忠实原型**：仅改动原型已覆盖界面（登录页 S1、首页“最近闯关”、“我的”），视觉严格遵循设计规范 v1.2，不新增原型外页面/元素。
3. **登录可切换**：真实登录与开发兜底登录通过配置切换，切换时无需改业务代码。
4. **数据权威在服务端**：登录态下的 XP、历史、统计以服务端为准。
5. **失败与空态**：登录失败、网络异常、无数据等均有明确、鼓励式的提示（沿用现有文案风格）。
6. **合规延续**：延续现有输入侧敏感词校验；用户昵称等 UGC 文本的合规校验按现有策略处理。

## 8. 前置依赖与待确认清单

在进入方案设计 / 开发前需具备或确认：

1. **MySQL 连接**：需提供可用的 MySQL 连接信息（host / 端口 / 用户名 / 密码 / 库名，或完整连接串）。库需提前存在，表可由程序自动创建。
2. **微信登录凭证（可选）**：真实模式需要 AppID + AppSecret；未提供则默认走开发兜底模式，不阻塞开发。
3. **XP 计算口径**：见 5.5 待确认项。
4. **昵称/头像获取方式**：确认采用微信当前官方推荐的头像/昵称获取方案。
